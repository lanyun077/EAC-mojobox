# 官方分类与作者标签

Mojobox 用少量、宽泛的官方标签组织目录，用作者标签补充特色。两者独立保存；作者标签
即使与官方 ID 同名，也不会自动变成官方分类。分类只说明用途或主题，不是安全、兼容或运行认证。

## 1. 先选资源类型，再选标签

功能与工作流整合包使用「用途」组；外观归档与皮肤 Prompt 资料使用「主题」组。
现有收录记录的 `category: function / workflow / appearance` 仍表示资源类型，不改成下列标签。
独立插件这次仍沿用现有检索，不向严格校验的插件信息卡或下游 v1 接口新增分类字段；Skill 不收录。

官方词表的事实源是 [`policies/catalog-tags.json`](../policies/catalog-tags.json)，
由 [`schemas/catalog-tag-groups.schema.json`](../schemas/catalog-tag-groups.schema.json) 校验。
每组最多 8 个标签，ID 稳定，中文名称和说明可维护；不根据投稿、组件名或热门角色自动扩充。

### 整合包用途：7 个

| ID | 名称 | 覆盖范围 |
| --- | --- | --- |
| `general` | 通用增强 | 日常综合工具、客户端体验、插件管理、恢复与维护 |
| `development` | 开发编程 | 代码编辑、项目工作区、开发辅助与项目管理 |
| `conversation` | 会话与智能体 | 会话管理、上下文、记忆、人设、多智能体协作 |
| `office` | 办公创作 | 文档、表格、内容制作与交互展示 |
| `research` | 检索分析 | 联网研究、资料检索、图像理解与数据分析 |
| `automation` | 自动化集成 | 浏览器／电脑操作、任务自动执行、外部服务连接 |
| `entertainment` | 娱乐互动 | 宠物、表情、趣味交互与陪伴 |

按主要用途选择，通常 1～2 个，最多 3 个。不要把每个附带组件的用途都贴上去。
`general` 有明确的日常工具范围，不是拿不准用途时的兜底。

### 皮肤主题：8 个

| ID | 名称 | 覆盖范围 |
| --- | --- | --- |
| `generic` | 通用设计 | 以配色、排版、基础控件或可配置外观为主，不突出特定题材 |
| `anime` | 二次元 | 动漫角色、虚拟偶像、动漫风原创人物 |
| `game` | 游戏主题 | 游戏世界、角色或视觉体系 |
| `nature` | 自然风景 | 海洋、山水、森林、天空、动植物及其艺术化表现 |
| `traditional` | 国风传统 | 水墨、传统纹样、书法、古典建筑等文化视觉 |
| `retro` | 复古怀旧 | 旧操作系统、早期软件、经典年代视觉 |
| `tech` | 科技工业 | 科幻、赛博、机械、工业面板等视觉 |
| `interface` | 界面仿真 | 模仿现实软件、设备或专业界面，不代表提供对应业务功能 |

角色、作品、颜色、材质、具体组件名保留为作者标签，不再分别增加官方分类。
标签允许交叉，例如游戏主题加科技工业；游戏主题不自动等于二次元。
明暗主题、动态效果、交付形态、加载器与兼容范围仍使用各自字段，不混成分类标签。

## 2. 投稿：只补一个网站标注条目

不修改作者归档、插件信息卡或外部 Prompt 清单。在
[`catalog/website-tags.json`](../catalog/website-tags.json) 的 `entries` 中添加自己资源的条目：

```json
{
  "type": "pack",
  "id": "org.example.tools",
  "officialTags": ["development"],
  "customTags": ["代码审查", "作者特色"]
}
```

- `type`：功能或外观 Feature Pack 都写 `pack`；皮肤 Prompt 资料写 `skin-prompt`。
- `id`：对应已收录资源的精确稳定 ID。类型与 ID 的组合不可重复，不能为不存在的资源建条目。
- `officialTags`：可选，从对应组选择 1～3 个不重复的英文 ID；不能使用另一组的标签。
- `customTags`：可选，1～12 个不重复自由标签，每个 1～32 字符，不能全为空白。
- 至少填写一种标签。可以只写自定义标签，由维护者审核时补充官方归类；也可两种同时写。

例如只投递皮肤作者标签，不确定官方分类：

```json
{
  "type": "skin-prompt",
  "id": "example-skin",
  "customTags": ["初音未来", "玻璃", "蓝色"]
}
```

已有收录记录或原始 Prompt 清单中的 `tags` 保留为作者标签，无需搬迁、重复填写或重算摘要。
缺少网站标注条目也不妨碍资源收录，页面显示「未分类」；不能为了消除未分类而猜测用途。
网站标注是 PR 审核内容，选了官方 ID 不等于可以跳过维护者审核。

仅调整网站标签不需要递增包版本或重打归档。资源撤下时同时移除对应网站标注，避免悬空引用。
分类文件的正反例见 [`fixtures/catalog-tags/`](../fixtures/catalog-tags/)，字段约束见
[`schemas/website-tags.schema.json`](../schemas/website-tags.schema.json)。

## 3. 网站如何使用

| 行为 | 官方标签 | 作者标签 |
| --- | --- | --- |
| 分类筛选、列表分类标识 | 使用 | 不使用 |
| 标签文本检索与相关性加权 | 使用 ID、中文名及少量官方别名 | 不使用 |
| 详情页 | 「官方分类」 | 独立的「作者标签」，保留原文 |
| 自动产生分类 | 不允许 | 不允许 |

名称、ID、简介、作者、来源、组件等正常文字检索仍保留。例如「初音」可以命中资源名称，
但不能仅凭自定义标签命中，也不会产生「初音」筛选项。「动漫」是官方维护的「二次元」别名，
不是从作者标签动态学习的映射；不维护成百上千个角色别名。

同组标签多选取并集，与关键词、资源形态等其他条件取交集。分类旁的数字来自当前资源类型
的完整目录，不随关键词或形态筛选变化。没有资源的标签默认隐藏，已选官方分类仍可显示 0；
存在未标注资源时显示「未分类」。URL 使用逗号分隔多个 ID，例如：

```text
#/skins?tag=anime,game&kind=prompt
```

旧作者标签链接或未知标签不会创建官方选项；没有任何有效命中时显示空结果和清空提示。
切换类型清空条件；详情返回、刷新和浏览器前进后退保留当前条件。

## 4. 首批标注依据与维护边界

本轮标注覆盖已有 14 个功能整合包、8 个外观归档与 10 套 Prompt 资料。
依据为现有作者清单、简介与 Prompt 设计说明，不声称实际运行验证。

- 初音、女仆工坊和鲸鱼娘系列归「二次元」，不为每个角色单列分类。
- 蓝色幻想与鲸吟按海洋、鲸群的设计说明归「自然风景」，不因有插画就推定二次元。
- Minecraft 归「游戏主题」；终末地归「游戏主题＋科技工业」。
- XP、QQ2008 归「复古怀旧＋界面仿真」；同花顺与交易终端只标「界面仿真」，不暗示交易能力。
- Bloom 以配色主题为依据先归「通用设计」，不因为配色名称有中国风就推定全套视觉是国风。
- Wallpaper Engine 可加载用户自选素材，归「通用设计」，不猜测用户实际壁纸题材。

新增官方标签须单独说明：现有组为何不能覆盖、是否能服务一批资源、是否与其他项重复。
超过每组 8 项需要明确调整词表策略和 Schema，不能作为一次普通资源投稿顺带放宽。

构建在替换生成目录前校验词表、条目格式、官方组、身份与重复项；不执行资源或联网分类。
`catalog.json` 增加网站专用 `tagGroups` 和每项 `websiteTags`，不是新的稳定下游 API。
`generated/api/v1/plugins.json`、其 Schema、作者归档、原始 Prompt 文件、Lock/Evidence 均不因分类改变。

## 5. 参考与验证

- [Modrinth 分类词表](https://api.modrinth.com/v2/tag/category)：按资源类型维护平台词表；借鉴维度分离，不照搬 Minecraft 类别。
- [Modrinth 搜索筛选](https://docs.modrinth.com/api/operations/searchprojects/)：同维度并集、跨条件交集的组合方式。
- [VS Code 扩展清单](https://code.visualstudio.com/api/references/extension-manifest)：区分固定 `categories` 和作者 `keywords`；Mojobox 按项目决策不索引作者标签。

运行 `npm test`、根路径与仓库子路径 `npm run build`、`npm run verify:downloads`、
`node authoring/build.mjs --check`、`git diff --check`。网站验收还需检查多选、计数、未分类、
自定义标签隔离、共享链接、中文输入、详情返回、浏览器历史和窄屏布局。

2026-10-20 本地验收：168 项测试中 166 项通过，2 项 Windows 符号链接测试跳过。
根路径、`/EAC-mojobox/`、`/dsh-mojobox/` 构建与下载复核通过（46 个归档、10 套资料）；
演示构建与下载复核通过。Edge 在三种路径的 1440、390、320px 下验证多选、关键词与形态
交集、作者标签隔离、刷新、详情返回、前进后退、键盘焦点及投稿指南，无页面异常或横向溢出。
插件来源 v1 JSON 与两份公开 Schema 的 SHA-256 与修改前一致，22 个自制包可按原字节重建。
浏览器验收屏蔽了外部预览请求，不验证远端图片可用性；不安装或运行收录资源。
