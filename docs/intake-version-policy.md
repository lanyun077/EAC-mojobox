# 收录版本声明策略

日期：2026-10-04。对应 [Issue #18](https://github.com/DSH-EAC/EAC-mojobox/issues/18)
与 [Issue #19](https://github.com/DSH-EAC/EAC-mojobox/issues/19)。
本文描述本地实现与维护决策，不代表已经合并、上线或获得上游批准。

## 1. 收录与安装分开

Mojobox 服务多个下游和不同内核版本。收录检查要求声明完整、语法合法，但不读取构建机器的
内核，不根据维护者本机版本拒绝面向旧内核的合法包。CI 和本地使用相同归档与政策得到相同结果。

`authoring/suite-curation.json.targetDsh` 是我们自制功能组合的选型目标，不是整个目录唯一允许的内核。
宿主在安装时根据实际内核、Profile 和 loader 判断适配及拒绝安装；Mojobox 不执行这个过程。

## 2. 新收录与更新版本

- 根 `pack.json.requires.dsh` 必填，采用 `semver` 库校验非空范围语法。不接受空对象、空白、
  `latest`、四段版本、空的 `||` 分组或非法预发布版本。合法范围可以面向旧内核。
- `*` 可以表达作者明确声明不限内核，但不能把未知支持范围写成 `*`。这一真实性要求由人工审核确认。
- npm 和 `github:owner/repo` 引用必须填写规范的精确 SemVer，支持预发布和 build 元数据。
  不接受 `latest`、通配符、区间、`^`、`~`、部分版本或 `v` 前缀。
- `builtin:` 遵循上游只核验组件存在的语义，可以不写版本。填写时须为精确 SemVer，但
  不声称宿主会按此安装或锁定内置组件。
- 不改写 `vendor/eac/`；更严格的外部版本声明是 Mojobox 收录政策，不冒充上游规范。
- 未知内核范围先留在候选区，由作者确认后提交正式收录；不自动修改作者归档。

`>=0.1.7-rc.2 <0.1.8.0` 因四段版本而语法非法；若作者本意为 `<0.1.8`，应由作者确认并发布
更正版本。语法非法和“不覆盖某个目标内核”是不同问题，不混为一谈。候选原始字节保持不变。

这里不实现版本覆盖判定，因此没有默认内核、回退内核或 RC 宽容匹配。
上游特定 matcher 支持的语法子集和预发布宽容策略，仍需由消费方检查。
未来如果做目标索引，须先对齐或共享上游 matcher，再绑定明确版本与规则来源；不能直接把
标准 SemVer 的默认预发布匹配结果当成上游语义。本轮不新增这个接口。

## 3. 八个历史皮肤归档

现有来源资料不足以确认全部皮肤的内核范围，不把子包依赖或构建电脑版本推断为整体兼容范围。
`policies/intake-legacy.json` 固定八个已有皮肤 `0.1.0` 的 ID、版本与实际归档 SHA-256。

只有三者完全一致的原始归档可以暂时缺少 `requires.dsh`。此例外只豁免缺失范围，不豁免
布局、摘要、插件版本、其他结构或来源记录检查；同 ID 新版本、字节变更或其他皮肤均不继承。
历史例外属于维护政策，不是作者提交材料，不应为接纳新贡献追加例外。

迁移按每个包独立进行：作者确认范围及依据，更新自制清单并递增包版本，创建新归档，计算真实
摘要并更新收录记录。旧归档不得覆盖、删除或重命名；旧运行证据不挪用。标签、介绍与截图的
独立更新不需要改归档，不改变原有例外身份。未确认前保留明确的未知状态，不声称迁移全部完成。

## 4. 数据与检查报告

`pack.json` 是版本声明的唯一事实源，不在收录 JSON 再复制兼容范围和插件列表。
生成 `catalog.json` 已投影 `requires` 与 `components`，本次新增以下报告字段并同步投影：

```json
{
  "versionDeclarations": {
    "policy": "mojobox-intake-v1",
    "kernel": "declared",
    "plugins": "exact-external",
    "comparison": "not-performed"
  },
  "warnings": []
}
```

普通包的 `checks` 新增 `manifest-requires-range` 和 `manifest-plugin-versions`。
历史包为 `kernel: legacy-undeclared`，带未知兼容警告，不把范围检查列为通过。
网页同步展示历史未知状态、语法检查与未执行内核比对。下载复核重新检查归档并比较上述字段，
不能改目录或报告把未知伪装成通过。

所有包保留 `runtime: not-tested`、`references: not-resolved`。固定外部插件版本并不锁定
GitHub commit 或插件产物摘要，更不意味着插件来源已解析、安装可复现、运行兼容或安全认证。

## 5. 验收

正反 fixture 和测试覆盖缺内核范围、非法范围、缺外部版本、版本范围、规范的 RC/build 版本、
旧内核范围合法收录、builtin 语义、精确历史例外及更新不继承、失败保留已有输出、报告篡改拒绝。

```powershell
npm test
npm run build:intake
npm run build
npm run verify:downloads
node authoring/build.mjs --check
npm run build:demo
npm run verify:downloads -- dist-demo --allow-demo
git diff --check
```

网站还须通过仓库子路径构建与桌面/窄屏检查。CI 不执行收录插件，也不将例外误报为版本声明已通过。

本地验收结果：122 项测试中 120 项通过，2 项 Windows 文件符号链接权限跳过，零失败。
根路径及 `/dsh-mojobox/` 子路径构建和下载复核通过：22 个归档、10 套皮肤资料。
自制包原样重建核对和 demo 下载复核通过；连续两次目录构建的 98 个文件摘要完全一致。
Playwright 在 1440、390、320 宽度检查普通包和历史包详情、检验状态，无横向溢出或脚本异常。
旧归档、生产收录记录、作者清单和上游 Schema 均未修改；未执行插件、安装或内核兼容测试。

依赖安装的 `npm audit` 另报告现有间接依赖 `brace-expansion` 和 `fast-uri` 两项高危问题，
本轮仅新增 `semver`，没有升级这两个依赖；不以构建通过表示依赖审计通过。

## 6. Issue 回复草稿

### 回复 #18

已确认缺失版本声明的情况，认可补齐收录信息的方向。我们正在本地实现 Mojobox 自有收录政策：
新收录及更新版本必须提供合法、非空的 `requires.dsh`，npm/GitHub 引用须声明精确插件版本，
不修改上游 Schema。`builtin:` 按宿主提供组件的上游语义处理，不要求虚构独立插件版本。

已有 8 个皮肤归档缺少可靠的整体内核范围，不能为了过门禁编造兼容声明。我们按 ID、版本和
SHA-256 精确保留原始字节例外，在报告和网页明确标记兼容未知；新版本不继承，作者确认后
递增版本迁移。兼容范围和插件列表继续以原始清单为事实源投影至目录，不增加重复副本。

检查只证明版本声明语法，不证明来源解析、安装可复现或运行兼容。候选示例中的 `<0.1.8.0`
也需要作者确认更正：它不是标准 SemVer，不能把语法错误与目标版本失配当成同一种反例。

### 回复 #19

认可对版本声明进行静态校验，并如实区分“已检查”和“未判定”。但不会采用本机内核作为总目录
的收录门禁：Mojobox 面向不同版本的下游，旧内核适用的包仍可收录；构建机器及 CI 的环境不应
改变收录结论。自制包的 `targetDsh` 也不能代表整个目录的统一支持目标。

当前报告明确标记内核覆盖判定未执行，不声称兼容通过。建议将本需求调整为明确目标版本的
索引筛选：完整目录保留资源，特定宿主索引再筛选适配声明；安装期仍由宿主按用户实际内核
拒绝。后续筛选实现需对齐上游的范围语法与 RC 宽容语义，本轮不自行实现另一套 matcher。
